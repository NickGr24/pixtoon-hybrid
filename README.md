# Pixtoon — сайт

Сайт pixtoon.com: главная, «Лучшие работы», «Капабилити», «Студия» и раздел
Hybrid Production с пятью страницами кейсов. Каждая страница на английском
и румынском — **двадцать страниц**.

**Демо:** https://nickgr24.github.io/pixtoon-hybrid/
(закрыто от индексации — на постерах ещё не опубликованные работы клиента)

Сборка отдаёт **плоский HTML + CSS + JS** — ровно то, что заводится в MODX как
шаблон и чанки. Eleventy нужен только нам, на прод он не едет.

## Запуск

```bash
npm install
npm run dev      # http://localhost:8080
npm run build    # сборка в dist/
```

> **Если `npm` падает с `dyld: Library not loaded: libllhttp.9.3.dylib`** —
> сломан Node из Homebrew, а не проект. Рабочий бинарник:
> `export PATH="/opt/homebrew/Cellar/node@22/22.22.2_1/bin:$PATH"`

## Что где

```
src/
  _data/
    site.json          контакты, соцсети, футер — сняты с живого pixtoon.com
    cases/             по файлу на кейс Hybrid Production, EN + RO
    cases.js           собирает их, считает флаги видео и карту кадров
    siteCases.json     четыре работы витрины главной (страниц кейсов не имеют)
    i18n/en.json       тексты всех страниц
    i18n/ro.json
    casePages.js       разворачивает 5 кейсов x 2 языка в 10 страниц
  _includes/
    layouts/base.njk   <head>, шапка, футер, подключение стилей
    partials/
      header.njk       шапка
      footer.njk       футер
      sections/        секции, переиспользуемые несколькими страницами
  pages/
    home.njk           главная
    work.njk           лучшие работы
    capabilities.njk   капабилити
    studio.njk         студия
    landing.njk        лендинг Hybrid Production
    case.njk           страница кейса, все десять из одного шаблона
  assets/
    css/               модули; склеиваются в hybrid.css и hybrid.min.css
    js/hybrid.js       ~7 КБ, без зависимостей; минифицируется в hybrid.min.js
    img/               кадры кейсов, Microinvest, главная
tools/
  crop-cases.mjs       нарезка кадров страниц кейсов из присланных исходников
  encode-videos.mjs    перекодирование роликов кейсов под веб
```

Рядом с крупными кадрами лежат уменьшенные копии — `-400`, `-600`, `-800`,
`-900`. Они перечислены в `srcset`, и телефон берёт ту, что отвечает его
экрану: первый экран раздела Hybrid тянул 760 КБ ради ячеек в 187 пикселей,
теперь около 140. Копии кадров главной и витрины сделаны `ffmpeg` вручную;
появится новый кадр — достаточно повторить
`ffmpeg -i кадр.jpg -vf scale=400:-2 -q:v 6 кадр-400.jpg` и дописать размер
в `srcset`.

### Кадры страниц кейсов

Эти лежат отдельно — `assets/img/cases/<slug>/<слот>.jpg` — и вручную не
режутся: пять кейсов по шесть-двенадцать слотов в трёх размерах дают около
сотни файлов, и ручной `ffmpeg` там гарантированно разъедется.

```bash
node tools/crop-cases.mjs                     # исходники из Telegram Desktop
node tools/crop-cases.mjs --only=drive-gas
node tools/crop-cases.mjs --pkg=/путь/к/пакету # посты кампаний, листы персонажей
```

Исходники — присланные клиентом скриншоты кадров из роликов и две HQ-раскладки
макета; в репозиторий они не кладутся (25 файлов по 2–9 МБ), коммитятся
результаты. Соответствие «кадр → слот» и точки интереса — таблица `CASES`
в самом скрипте.

Набор `srcset` собирает одноимённый фильтр по факту наличия копий на диске:
скрипт не делает копию шире базы, и кадр в 600 px существует без `-800`.
Записанный руками список обещал бы браузеру файл, которого нет.

Правка текста — в JSON, не в разметке. Правка шапки — в одном `header.njk`,
а не в двадцати файлах.

### Переиспользуемые секции

Пять секций встречаются больше чем на одной странице: `capabilities`,
`process`, `studio-stats`, `selected-work`, `lets-talk`. Они лежат в
`_includes/partials/sections/` и принимают переменную `showHead`.

`showHead: false` выключает собственный заголовок секции — это нужно на
подстраницах, где над секцией уже стоит заголовок страницы. В макете base44
подстраницы дублируют свой H1 в H2 секции, и на `/work`, `/capabilities` и
`/studio` один и тот же текст идёт двумя заголовками подряд. Дубль убран по
просьбе клиента.

### Страницы кейсов

Раскладка снята с двух HQ-макетов клиента
(`PIXTOON_Microinvest_Case_Study_HQ.png` и `PIXTOON_DriveGas_Case_Study_HQ.png`),
тексты — с документа `PIXTOON_Hybrid_Production_Case_Studies_RO.docx`
(29.08.2026). Английские переведены с румынских.

Порядок секций у всех пяти одинаковый, потому что документ даёт им одинаковую
структуру: рассказ, перечень работ, процесс, панель сравнения, крупная фраза,
кадры, итог, условия применимости.

Различается **герой** — `pano` (панорамный кадр во всю ширину, мета строкой в
четыре колонки под ним) или `portrait` (мета столбиком, вертикальный кадр
сбоку); выбор задан полем `hero` и следует за форматом материала кейса. Bere
Chișinău остался портретным: у него весь исходный материал вертикальный, и
панорамная обрезка оставила бы от бутылки поясок.

**Секции контента** перечислены в `page.sections` и берутся из закрытого
списка типов:

| `type` | Что это |
|---|---|
| `story` | заголовок с волнистым подчёркиванием, абзацы слева, кадр или клип справа |
| `list` | то же плюс список с галочками; без кадра список раскладывается в две колонки |
| `process` | шаги `01…05`: кадр, номер, подзаголовок, текст; пунктирные дуги между |
| `compare` | заголовок кейса и панель на две колонки с чек-списками |
| `statement` | одна крупная контурная фраза с «искрами» по бокам |
| `cards` | заголовок и ряд карточек с плашками; `cols` задаёт 3 или 4 в ряду |
| `outcome` | заголовок из трёх утверждений слева, чек-лист и стрелка справа |

`flip` у `story` и `list` меняет стороны местами — вместе с шириной колонок, а
не только порядком: колонки неравные (442 и 736), и один `order` отдал бы
кадру узкую половину.

Тексты `process` и `compare` лежат в `i18n`, а не в кейсе: они описывают
пайплайн студии, который у всех пяти один. Кейс приносит кадры шагов и свой
заголовок с подводкой к панели сравнения — у каждого свой довод, почему гибрид
выбран именно здесь. У кейсов без подходящих исходников шаги идут без кадров:
повторить один снимок пять раз хуже, чем честный ряд из номера и текста.

Слоты кадров адресуются по имени (`card-2`, `sheet-1`, `clip-rig`). Опечатка
роняет сборку с указанием кейса, слота и списка доступных — проверку делает
`cases.js`, потому что молча битая картинка на живой странице обходится
дороже. У клипа проверяются оба файла: и mp4, и постер.

Плашки поверх кадров (`VIDEO 9:16`, `FORMAT VERTICAL`) рисуются разметкой, а
не запекаются в JPEG: иначе они не переводятся на вторую локаль и мылятся при
масштабировании.

**Рукописный слой** второй раскладки делится надвое. Пометки вроде
«scenă din film de brand» — это текст: набираются Caveat (`--hyb-font-hand`),
переводятся и правятся в JSON. Волна под словом, дуги между шагами, стрелки и
«искры» — фигуры, они лежат в `icons.js` рядом с остальными контурами и
одинаковы в обеих локалях.

### Ролики кейсов

Мастера приходят по 100–430 МБ (4K .mov и HEVC), в репозиторий не кладутся.
Перекодирование — `tools/encode-videos.mjs`; коммитятся результаты.

```bash
node tools/encode-videos.mjs
node tools/encode-videos.mjs --only=drive-gas
```

На кейс два файла: `<slug>.mp4` — полный ролик со звуком для страницы, и
`<slug>-preview.mp4` — 8 секунд без звука для наведения на карточку в сетке.
Одним не обойтись: наведение на карточку тянуло бы весь мастер.

Третий вид — **закулисные клипы**: девятисекундные куски записей экрана из
продакшена (моделирование по референсу, playblast, риггинг) и тест действий
персонажа. Они лежат не отдельно, а в папке кадров кейса, под тем же именем,
что их постер: `clip-rig.mp4` рядом с `clip-rig.jpg`. Секция просит клип полем
`clip`, и рассинхрон имён невозможен по устройству.

```bash
node tools/encode-videos.mjs --what=clips
```

Клип играет беззвучно по кругу и запускается сам, когда доезжает до экрана;
уезжает — останавливается. Кнопки и панели у него нет: включать нечего,
перематывать нечего. Источник подставляется при первом появлении, а не в
разметке, — до клипа на странице ещё половина текста. Ничего не запускается
при `prefers-reduced-motion` и при включённой экономии трафика: в обоих
случаях на месте клипа остаётся постер.

`-movflags +faststart` обязателен — без него индекс mp4 лежит в конце файла,
и браузер не начнёт воспроизведение, пока не скачает ролик целиком.

Кнопка воспроизведения включается сама: `cases.js` считает `hasVideo` по
факту наличия файла на диске — положили mp4, кнопка появилась.

**Перемотка требует Range-запросов от сервера.** `python -m http.server`
отвечает `200` на любой `Range`, и перемотка в такой раздаче не работает
вообще — при локальной проверке нужен сервер, отдающий `206 Partial
Content`. К самим файлам это отношения не имеет.

### Плеер страницы кейса

Свои органы управления вместо нативного `controls`: кадр кадрируется по
контейнеру (`object-fit`), а панель браузера рисуется внутри самого видео —
она уезжала за границу фигуры, и перемотать ролик было нечем.

Ползунок — обычный `input[type=range]`: он бесплатно даёт перемотку с
клавиатуры, роль `slider` для скринридера и перетаскивание на тач-экране.
Иконки состояний лежат в разметке обеими парами, показ переключает CSS —
скрипт трогает только классы и подписи, контуры остаются в `icons.js`.

При запуске контейнер подгоняет пропорцию под ролик (`aspectRatio` из
`videoWidth/videoHeight`): кадр героя бывает панорамным 2.9:1, а ролик —
16:9 или вертикальным, и без этого видео либо обрезалось бы, либо висело в
чёрных полях.

Клавиши при фокусе на кадре: пробел или `K` — пуск и пауза, стрелки — ±5
секунд, `M` — звук, `F` — во весь экран.

## Дизайн-система

Значения не срисованы на глаз: они сняты с живого макета base44 через CDP —
вычисленные стили всех видимых элементов, сгруппированные по ролям. Живут в
`src/assets/css/tokens.css`.

| Что | Значение |
|---|---|
| Заголовки | Baloo 2, интерлиньяж ровно 1.0 |
| Текст | Quicksand |
| Пометки от руки | Caveat, только на страницах кейсов |
| Акцент | `#8f71a8` |
| Золото | `#b99655` |
| Чернила / приглушённый | `#231e29` / `#56515d` |
| Фоны | `#ffffff` / `#f5f1f8` |
| Границы | `1px solid #e6e1ea` |
| Скругления | пилюля, 24, 16 |
| Тени | нет — глубину даёт граница и разница фонов |
| Контейнер | 1280 |

**Кнопки — четыре роли:** золотая (главный призыв в контенте), сиреневая (CTA
в шапке), тёмная (выбор пакета), призрачная (вторичное действие). Жёлтый
`#fff028` со старого сайта из проекта убран.

**Четыре цвета имеют затемнённые парные токены** (`--hyb-accent-text`,
`--hyb-gold-text`, `--hyb-gold-large`, `--hyb-cta`): цвета макета не проходят
пороги контраста на мелком тексте и на крупных цифрах. Подробности — в
комментариях `tokens.css` и в `docs/CONTENT-REVIEW.md`.

Один outline-заголовок на секцию. Шорткод `title` принимает единственное поле
`outline`, поэтому продублировать приём внутри секции нельзя технически. Он же
связывает односимвольные слова неразрывным пробелом — замечание клиента
«litera O nu poate fi așa în aer».

## Проверка

Скрипт сквозной проверки лежит в истории работ, а не в репозитории; критерии
приёмки такие:

1. `npm run build` проходит, в `dist/` двадцать страниц
2. На каждой странице ровно один `h1`, нет двух одинаковых заголовков подряд
3. Нет висячих односимвольных слов в заголовках — на 1440 и 390, обе локали
4. Нет битых внутренних ссылок и картинок, нет горизонтального переполнения
5. Жёлтый `#fff028` не встречается
6. У каждой картинки есть `width`, `height` и `alt`, все пути `srcset` ведут
   в существующие файлы
7. На страницах кейсов нет пустых слотов: рендерятся только те секции, что
   перечислены в данных кейса
8. Один outline-заголовок на секцию
9. Каждый кадр в `assets/img/cases/<slug>/` кто-то запрашивает: слот, которого
   нет в данных, — это забытый файл, а не запас

## Демо на GitHub Pages

Pages настроены на ветку `gh-pages` (режим legacy), а не на Actions. Обновить
после правок:

`npm run build` начинается с `rm -rf dist`. Без очистки каталог хранит
страницы удалённых и переименованных кейсов: `medpark-doctor-buba` пережил
переименование в `medpark-mafa-girafa` и уехал бы в демо вместе с новой
страницей.

```bash
PATH_PREFIX=/pixtoon-hybrid/ npm run build

git worktree add /tmp/ghp gh-pages
git -C /tmp/ghp reset --hard origin/gh-pages
rsync -a --delete --exclude=.git dist/ /tmp/ghp/
git -C /tmp/ghp add -A && git -C /tmp/ghp commit -m "Демо: …"
git -C /tmp/ghp push origin gh-pages
git worktree remove /tmp/ghp
```

Через worktree, а не `cd dist`: каталог `dist/` лежит в `.gitignore` и своей
истории не имеет. `reset --hard origin/gh-pages` перед копированием
обязателен — иначе устаревшая локальная ветка откатит чужие коммиты демо.

`PATH_PREFIX` обязателен: Pages отдаёт сайт из подпапки, без префикса ссылки
уедут в корень домена. Для боевой сборки переменная не задаётся.

Workflow `.github/workflows/deploy.yml` удалён: он использовал
`actions/deploy-pages`, который работает только когда Pages переключены в
режим `workflow`. В режиме legacy он падал после каждого пуша, ничего при
этом не публикуя.

## Интеграция в MODX

1. `npm run build` → каталог `dist/`. **Без `PATH_PREFIX`** — на pixtoon.com
   пути должны быть корневыми.
2. `assets/css/hybrid.min.css`, `assets/js/hybrid.js`, `assets/img/*` положить
   в те же пути на сервере. В HTML подключён именно `.min` — рядом лежит
   `hybrid.css`, тот же файл с комментариями: он для чтения и правок, в
   браузер посетителя ехать ему незачем (87 КБ против 35).
3. Шрифты Baloo 2, Quicksand и Caveat подключаются из Google Fonts одной
   ссылкой в `<head>`.
   Параметр `subset=latin,latin-ext` обязателен: без него ș, ț, ă, î
   подставятся из системного шрифта и румынский текст поедет по начертанию.
4. **Шапку и футер завести заново.** Раньше здесь стояла оговорка «заменить
   существующими чанками сайта, структура и классы совпадают» — после смены
   дизайна она недействительна: оболочка теперь наша, разметка и классы
   другие, и стили её едут в `hybrid.css`. Файла `theme-shell.css` больше нет.
5. Секции завести чанками. Класс `hyb-scope` обязателен — на нём объявлены все
   токены; он стоит на `<body>`, а не на `<main>`, потому что шапка и футер
   тоже читают токены.
6. Ресурсы MODX: главная, `work`, `capabilities`, `studio`,
   `hybrid-production` и пять дочерних по slug кейсов, плюс те же в контексте
   `ro`.

Весь CSS под префиксом `.hyb-*`.
